# Business summary

For: BA, PO, tester, end user, or any stakeholder who does not read code.

```markdown
# <change, in business terms>

## What changed
What the system does now that it did not before, described through what a user
does and sees.

## Why
The business reason or the problem it solves.

## Who is affected
Roles, screens, and flows. Include anyone whose existing routine changes.

## Before and after
| Situation | Before | Now |

## What to check
Numbered steps a tester or user can follow, each with the expected result.

## Not changed
Behavior people might reasonably expect to have changed and which did not.

## Open points
Decisions still needed, or known limitations. `None.` when there are none.
```

No class, method, controller, repository, SQL, file path, or framework name.
If the reader would need to open the code to understand a sentence, rewrite it.
